# P1 learning notes: MemoryGraph local MVP

## What was built

MemoryGraph now has a small, reproducible retrieval pipeline and a local interface. It creates fictional coding preferences, compares lexical and pretrained embedding retrieval, stores editable memories, and shows exactly which memories enter an optional local model prompt. It does not yet test whether memory improves coding correctness for real users.

## Data flow and key files

1. `experiments/config.py` fixes the seed, synthetic scenarios, validation folds, embedding revision, and local inference settings before runs.
2. `src/memorygraph/data.py` builds the fictional query-memory pairs. `experiments/run_baselines.py` trains grouped TF-IDF classifier baselines and saves raw predictions plus metrics.
3. `experiments/prepare_model.py` obtains a pinned embedding snapshot. `experiments/run_semantic.py` evaluates retrieval on the same synthetic pairs; `experiments/plot_results.py` produces the chart from saved metrics.
4. `src/memorygraph/store.py` and `retrieval.py` implement local memory edits, lexical/semantic ranking, and a small entity graph. `app.py` exposes these choices and the selected context.
5. `src/memorygraph/inference.py` sends an optional prompt to local Ollama. `experiments/run_inference_demo.py` logs two fixed prompt variants without executing or scoring generated code.

## Reading the results

On 600 fictional pairs, embeddings reached MRR 0.736 and precision@3 0.281; TF-IDF cosine reached MRR 0.516 and precision@3 0.197. The top-three maximum is 0.333 here because each query has only one relevant memory. A random forest achieved perfect classification F1, a sign that the templates expose shortcuts. These results do not estimate real-user benefit. The local two-prompt generation run logged 46 and 63 prompt tokens, with both outputs capped at 128 tokens; correctness and energy were not measured. A failed local connection attempt is also preserved in raw JSONL.

## Five questions to answer

1. Why does `GroupKFold` split by fictional user rather than by individual query-memory pair?
2. Why is precision@3 capped at one third for each query in this dataset?
3. What could make random forest F1 perfect even on held-out synthetic users?
4. Which files establish the exact embedding snapshot and local model settings?
5. Why can two generation calls with different token counts not establish a quality or latency benefit?

## Assumptions

- The fictional templates are useful for checking the pipeline, not for estimating human behavior.
- The owner approved Python 3.12 and the added packages for this MVP.
- The installed Ollama model is local; no remote API or private conversation history is used.
- Model-generated code remains plain text and is never executed.
