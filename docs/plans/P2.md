## Files and design

- `src/memorygraph/conflicts.py`: detect narrow, explicit conflicting preference statements and return IDs; never silently delete or rewrite memories.
- `src/memorygraph/retrieval.py`: retain ranked results for every candidate; leave scoring methods unchanged so published synthetic results remain comparable.
- `app.py`: clear stale retrieval after edits, show all candidate scores, let the user choose memories, require explicit approval before optional local generation, and block simultaneous conflicting preferences. Add a fictional walkthrough starter.
- `tests/`: add meaningful tests for conflict detection and selection policy.
- `docs/SPEC.md`, `docs/learning/P2.md`, `README.md`: explain current behavior, limits, and data flow. Existing raw results remain immutable.
- Portfolio source: lead the Research page with memory interference; rebuild MemoryGraph as an evidence-led case study with actual trace, code links, and screenshots when captured. Remove auditor language site-wide.
- Resume source: update links, education wording, portfolio URL, and MemoryGraph status; render both one-page versions and inspect links/text.

## Risks and limits

- Conflict detection recognizes only explicit phrases in a small vocabulary. It can miss implicit or contextual conflicts, so users remain in control.
- Candidate scores differ by method and must not be compared across methods as calibrated probabilities.
- The synthetic dataset has template shortcuts; classifier perfection must be presented as a limitation.
- The recorded generation is capped at 128 tokens; no generated code may be executed in the app.
- Older Scaler and InterviewForgeAI source may be unavailable; do not invent screenshots, results, or deployment links.
- Site updates are prepared locally. The owner requested separate approval before deployment.
